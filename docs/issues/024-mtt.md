## What to build

Implement MTT support in `sb-tournament` crate (REQ-FUNC-019) for 30–500 players:

- `POST /tournaments/mtt` with `max_players`, `buy_in`, `blind_schedule` (JSON schedule of levels).
- System creates multiple table actors (max 9 per table). Players are randomly seated.
- **Rebalancing logic:** When a table has ≤ 2 players, those players are moved to other tables (balanced by stack size) until one final table remains.
- Blind schedule advances on a fixed timer across all tables (coordinated by a parent tournament actor).
- Final table plays to one winner; prize pool distributed according to configurable payout structure (top 10–20% paid).
- Tournament state persisted in SQLite (`tournaments`, `tournament_registrations`, `tournament_results`).
- Use `sb-db-repos` for persistence commands.

## Acceptance criteria

- [ ] 30‑player MTT: initial 4 tables (9,9,9,3). When tables have 1–2 players, rebalance occurs.
- [ ] Blinds increase simultaneously on all tables (verified by checking that hand number across tables is same).
- [ ] Final table (9 players or fewer) plays to winner.
- [ ] Leaderboard reflects MTT chip wins after completion.
