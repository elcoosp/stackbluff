## What to build

Implement MTT support (REQ-FUNC-019) for 30–500 players:

- `POST /tournaments/mtt` with `max_players`, `buy_in`, `blind_schedule` (JSON).
- System creates multiple table actors (max 9 per table). Players are randomly seated.
- When a table has ≤ 2 players, those players are moved to other tables (rebalancing) until one final table remains.
- Blind schedule: levels (e.g., 10/20, 15/30, 25/50) advance on a fixed timer across all tables.
- Final table plays to one winner; prize pool distributed according to configurable payout structure (top 10–20% paid).
- Tournament state persisted in SQLite (`tournaments`, `tournament_registrations`, `tournament_results` tables).

## Acceptance criteria

- [ ] 30‑player MTT: initial 4 tables (9,9,9,3). When tables have 1–2 players, rebalance occurs.
- [ ] Blinds increase simultaneously on all tables.
- [ ] Final table (9 players or fewer) plays to winner.
- [ ] Leaderboard reflects MTT chip wins after completion.
